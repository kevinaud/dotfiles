# allpaste-script-creator

Create bash wrapper scripts around `allpaste` (~/bin/allpaste) that capture targeted
slices of a codebase as Markdown. Scripts are saved to `scripts/` in the repo root.

## allpaste CLI Reference

```
allpaste [OPTIONS]

--output=<file>         Write to file instead of clipboard
--include=<substrings>  Comma-separated substrings to include in file paths
--exclude=<substrings>  Comma-separated substrings to exclude from file paths
--rinclude=<regex>      Regex to include file paths
--rexclude=<regex>      Regex to exclude file paths
--truncate-pattern=<substrings>  Files matching these get truncated
--truncate-limit=<num>  Chars to keep when truncating (default: 1000)
--no-gitignore          Disable .gitignore filtering
```

Note: `--include` and `--rinclude` are mutually exclusive. Same for `--exclude`
and `--rexclude`.

## Wrapper Script Template

```bash
#!/bin/bash

# allpaste wrapper: <DESCRIPTION>
# Generated by allpaste-script-creator

# ==============================================================================
# CONFIGURATION
# ==============================================================================

# 1. INCLUDES - file path substrings that MUST match (comma-separated)
INCLUDE="<includes>"

# 2. EXCLUDES - file path substrings to reject (comma-separated)
EXCLUDE="<excludes>"

# 3. TRUNCATES - file path substrings whose matches get truncated
TRUNCATE_PATTERN="<truncate_patterns>"
TRUNCATE_LIMIT=1000

# ==============================================================================
# EXECUTION
# ==============================================================================

allpaste \
  --include="$INCLUDE" \
  --exclude="$EXCLUDE" \
  --truncate-pattern="$TRUNCATE_PATTERN" \
  --truncate-limit="$TRUNCATE_LIMIT" \
  "$@"
```

Omit any flag variable + corresponding CLI arg whose value is empty. Use
`--rinclude`/`--rexclude` instead when substring matching is insufficient (e.g.
matching file extensions across nested dirs). Pass-through `"$@"` at the end so
users can layer on extra flags.

## Workflow

### Phase 1: Explore the Codebase

1. Use Glob, Grep, and Bash (`ls`, `tree -L 2`) to understand the repo layout
   relevant to the user's request. Identify key directories, file types, patterns.
2. Note which areas are relevant vs noise for the user's stated goal.

### Phase 2: Draft the Script

1. Write a first-draft bash script to `scripts/allpaste_<name>.sh`.
2. Use includes to target relevant directories/file types.
3. Use excludes to filter out common noise: tests, generated files, lock files,
   binary assets, node_modules, dist, coverage, `.git`, `.DS_Store`, images
   (`.png`, `.jpg`, `.jpeg`, `.svg`, `.ico`, `.gif`, `.webp`), fonts (`.woff`,
   `.woff2`, `.ttf`, `.eot`), source maps (`.map`).
4. Make the script executable: `chmod +x scripts/allpaste_<name>.sh`.

### Phase 3: Execute, Analyze, and Iterate

1. Run the script with `--output=/tmp/allpaste_draft.md` to capture output to a
   file. **Capture stderr** which contains the stats:
   ```bash
   scripts/allpaste_<name>.sh --output=/tmp/allpaste_draft.md 2>&1 | head -500
   ```

2. **CRITICAL: NEVER read the output file** (`/tmp/allpaste_draft.md`). It will be
   very large and will overwhelm the context window. Only analyze the stderr stats
   (file list with char counts, total size).

3. Analyze the stats output:
   - Check total character count against the user's budget (if specified).
   - Identify unexpectedly large files that should be truncated or excluded.
   - Identify files that don't belong (tests, configs, generated code, etc.).
   - Look for entire directories that could be excluded.

4. If the output exceeds the budget or contains questionable files, use
   AskUserQuestion to present options:
   - Which file categories or directories to exclude
   - Which large files to truncate (and at what limit)
   - Whether certain file types are relevant or noise
   Provide concrete options based on the stats (e.g. "Exclude all `__tests__/`
   dirs - saves ~45k chars" or "Truncate `.json` configs to 1000 chars").

5. Update the script based on feedback and re-run. Repeat until the output is
   within budget and captures the right content.

### Phase 4: Final Verification

1. Run the script one last time and confirm:
   - Total chars within budget (if specified)
   - File list looks correct for the stated goal
   - No obvious noise or missing important files
2. Present the final stats summary to the user.

## Naming Convention

Scripts: `scripts/allpaste_<descriptive_name>.sh`
Examples: `allpaste_frontend.sh`, `allpaste_api_layer.sh`, `allpaste_infra.sh`

## Key Rules

- **Never read the allpaste output file** - only analyze stderr stats
- Always use `--output=/tmp/allpaste_draft.md` during iteration (not clipboard)
- Always pass `"$@"` at the end of the allpaste call
- Include a comment header describing what the script captures
- Prefer `--exclude` over `--rexclude` unless regex is truly needed
- When the user specifies a char budget, treat it as a soft target (within ~10%)
